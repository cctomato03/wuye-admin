# 小区物业管理系统 · 开发手册

面向接手开发/运维的工程师，约定本项目的分层、错误处理、多租户与数据权限、数据库迁移、测试与常见坑。

## 一、技术栈与目录

| 层 | 技术 |
| --- | --- |
| HTTP | Gin（中间件：恢复、CORS、请求日志、JWT 鉴权、权限校验、限流） |
| 数据 | MySQL 8 + GORM（软删除 `softDelete:milli`，DSN 必须 `parseTime=True&clientFoundRows=true`） |
| 缓存 | Redis（登录态黑名单、验证码、权限缓存、在线用户集合、分布式锁） |
| 前端 | Vue 3 + TypeScript + Element Plus + Vite，动态菜单 + `v-auth` 按钮权限 |

```
cmd/server            入口（配置、DB/Redis、路由、优雅退出）
internal/api          处理器：参数绑定 → service → response
internal/service      业务逻辑（每模块一个文件）
internal/repository   数据访问（通用查询、权限/用户查询）
internal/model/entity GORM 实体
internal/middleware   鉴权、权限、日志、限流
internal/bootstrap    装配、启动期结构校验 EnsureSchema、地址回填
internal/migrate      迁移执行器（schema_migrations）
internal/excel        Excel 读写
internal/openapi      Swagger 页面
pkg/                  errs、response、cache、jwt、storage、id、jsonx、logger
migrations/           版本化 SQL
web/                  前端
```

### 分层约定
- **api** 只做：绑定参数（`bindJSON` / `queryID` / `pathID`）、取当前主体 `principal.Must(c)`、调用 service、`response.Ok/OkData/Page/Fail`。
- **service** 承担：权限与租户校验、事务（`wrapTxErr` 保留业务错误）、跨表组合、业务规则。
- **repository** 承担：可复用的查询（如按角色取菜单/小区、批量取用户）。
- 禁止在 api 层直接写 SQL；禁止在 service 层拼接原始响应。

## 二、错误与响应

统一响应体：`{ code, message, data, traceId }`，`code=0` 表示成功。

```go
errs.Invalid("同一上级下已存在同名层级")   // 10001 参数/业务校验
errs.ErrNotFound / ErrForbidden / ErrDB / ErrInternal
response.Ok(c) / OkData(c, v) / OkID(c, id) / Page(c, list, total)
```

约定：
- 参数校验错误由 `response.BindErr` 翻译成中文（禁止把 `Key: 'Xxx.Field' Error:Field validation...` 抛给用户）；
- 事务内的业务错误用 `wrapTxErr(err)`，避免被包装成 50001；
- 路径参数用 `pathID`（非法返回「路径参数不正确（ID 必须是数字）」）。

## 三、多租户与数据权限

### 3.1 租户（物业公司）
- 所有业务表带 `tenant_id`；写操作取 `principal.Info.TenantID`。
- 平台超管：`IsSuper=true` 且绑定默认租户；`tenantIDOf(p)` 对其返回 0（不按租户过滤）。
- 登录未带 tenantId 时按账号全局查找（`FindUserByUsernameAnyTenant`）。

### 3.2 小区范围
- 角色可管理小区：`sys_role.community_scope` = 1（本公司全部）/ 2（指定，存 `sys_role_community`）。
- 登录主体计算：超管或存在 scope=1 角色 → `CommunityAll=true`；否则合并「角色指定小区 ∪ `pm_user_community` 直接授权」。
- 查询统一用 `scope.Tenant(p.TenantID)` 与 `communityScope`/`s.scoped(ctx, model, p, "community_id")`；
  写前用 `MustCommunity(ctx, p, communityID)`。
- 越权统一返回 403（`errs.ErrForbidden`）。

### 3.3 组织与权限的租户切换（平台 vs 公司）

- 组织与权限（用户/角色/部门/岗位/员工）默认按登录用户所属公司过滤；
- **平台默认租户**（tenant.default_id，默认 1）可在组织页切换任意物业公司（前端下拉，持久化键 org.currentTenantId）；
- 统一入口：Service.OrgTenant(ctx, p, requestedTenantID)：
  - requested=0 → 登录用户自己的租户；
  - requested=本人租户 → 允许；
  - requested=其它租户 → 仅平台默认租户允许，且目标租户必须存在，否则 403；
- 关联接口都接受 tenantId（查询参数或请求体），service 必须先 OrgTenant 再落库/查询：
  GET /system/users|roles|depts/tree|posts、POST/PUT system/users|roles|depts|posts、
  GET/POST /property/employees、/employees/dept-tree、/employees/roles；
- 公司管理员越权访问别家公司数据一律 403（E2E 已覆盖）。

### 3.4 角色基线（首次部署）

- 默认租户只内置两个角色：super_admin（全权限）与 pm_company_admin（物业管理员）；
- 物业管理员权限 = 全部菜单 − 系统设置(1300) − 系统监控(1200) − 菜单管理(1030) 及其子菜单；
  即：可管用户/角色/部门/岗位/员工与全部物业业务，但看不到平台级配置与菜单权限；
- 新建物业公司时按同一规则克隆该角色（名称「物业管理员」，community_scope=1 本公司全部小区）。

### 3.5 角色/用户越权防护
- `CreateRole/UpdateRole/GrantRole`：目标小区 ⊆ 调用者可管理小区；菜单 ⊆ 调用者已有菜单（超管除外）。
- `CreateUser/UpdateUser/AssignUserRoles`：角色必须属于本租户。
- 新建物业公司只内置一个「物业公司管理员」角色（除 系统监控/系统设置/物业公司与小区/菜单管理 之外全部菜单）。

## 四、数据库与迁移

### 4.1 表结构约定
- 主键：雪花 ID（`uint64`），JSON 以字符串下发（`json:"id,string"`）。
- 审计：`create_by/create_time/update_by/update_time`；软删除：`deleted BIGINT`（毫秒时间戳，0 为未删）。
- 唯一索引必须包含 `deleted`：`uk_xxx(col, deleted)`，否则软删后无法复用编码。
- 高频过滤列建复合索引并带 `community_id`（如 `idx_comm_node(community_id,node_id,deleted)`）。

核心业务表：

| 表 | 说明 |
| --- | --- |
| `pm_community` / `pm_company` | 小区（归属唯一物业公司）/ 物业公司档案 |
| `pm_structure_node` | **小区层级树**（小区为根，`parent_id=0` 即顶级）：`node_type`(类型)、`category`、层数/单元/电梯/面积、`full_address` 自动地址、`level_no/path` |
| `pm_house` | 房屋：`node_id` 挂层级（可 0=直接挂小区）、面积（建筑/套内/公摊）、用途/类型/状态、产权/临街/层高/设施 |
| `pm_house_type` | 房屋类型（户型模板） |
| `pm_resident` / `pm_resident_house` | 住户档案 / 房屋关系（身份、有效期、主联系人） |
| `pm_visitor` / `pm_other_person` | 访客登记 / 其他人员 |
| `pm_merchant` / `pm_vehicle` / `pm_parking_space` | 单位商铺 / 车辆 / 车位（均按 `house_id` 关联） |
| `pm_device` / `pm_access_*` | 设备（`bind_node_id` 绑层级）/ 门禁授权、卡片、下发日志 |
| `pm_fee_item` / `pm_fee_standard` / `pm_bill` / `pm_meter*` / `pm_account*` | 收费项目、标准、账单、抄表、账户与流水 |
| `sys_user/role/menu/dept/post/dict*/config/file/job/log*` | 系统与权限 |

### 4.2 迁移规则（重要）
- 迁移文件位于 `migrations/`，命名 `NNNNNN_说明.up.sql`，由 `schema_migrations` 记录版本，按文件名顺序执行。
- 迁移执行器把脚本按 `;` 拆成单条语句、每条可能使用连接池里的不同连接：**禁止**在迁移里使用会话变量/存储过程。
- MySQL 8 **没有** `ADD COLUMN IF NOT EXISTS`：所有「加列/加索引」放入 `internal/bootstrap/schema.go` 的 `EnsureSchema`
  （先查 `information_schema` 再执行，幂等），迁移文件只放数据变更（`INSERT IGNORE`/`UPDATE`）。
- 层级地址回填由 `EnsureNodeAddresses` 完成（只在存在空地址时执行）。
- 线上遇到 `Duplicate column name xxx`：说明 DDL 已生效但版本未记录 → `DELETE FROM schema_migrations WHERE version='...'` 后重启即可自愈。

## 五、接口与路由

- 前缀 `/api/v1`；鉴权：`Authorization: Bearer <accessToken>`；刷新令牌走 `/auth/refresh`。
- 权限：路由声明 `middleware.Perm("模块:资源:动作")`，权限码与菜单按钮绑定。
- 物业模块路由（节选）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/property/nodes/tree` | 层级树（含类型名、自动地址、房屋统计） |
| GET | `/property/nodes/children` | 树懒加载：子层级 + 直接挂载房屋（`parentId=0` 为根） |
| POST/PUT/DELETE | `/property/nodes[/:id]` | 层级增删改（名称同级唯一、类型校验、地址自动） |
| GET | `/property/nodes/:id/card` | 层级信息卡片（范围/房屋总数/住户/设备/地址） |
| GET | `/property/structures/houses` | 房屋列表（`nodeId`、`includeSub`、`rootOnly`） |
| POST | `/property/structures/houses(/batch)` | 新增/批量生成房屋 |
| GET | `/property/structures/houses/:id/card` | 房屋卡片（住户 + 车辆） |
| GET | `/property/spaces/summary` \| `/spaces/community-card` | 小区概览 / 小区卡片 |
| POST | `/property/spaces/clear` | 清空小区层级与房屋（逻辑删除；有住户/账单/车辆/单位/访客时拒绝；设备解绑） |
| GET | `/property/structures/import-template` \| `/spaces/export` | 导入模板 / 导出 |
| POST | `/property/structures/import` | Excel 导入（按房屋地址自动补齐层级，3 列模板） |

- 菜单为后端动态下发（`/auth/routes`）：`MenuProcessor.buildFullPath` 中**分组目录的 path 必须是子页面 URL 前缀**，子页面用相对路径，否则前端路由嵌套会失效。

## 六、Excel 导入导出

- 统一走 `internal/excel`（`Build` / `Read`），限制行数（导入 2 万行）。
- 小区基础信息模板（3 列）：房屋编码、房屋地址、房屋面积；模板示例地址按当前小区真实「地址+名称」生成。
- 地址解析：地址必须先匹配「小区地址 + 小区名称」前缀（忽略空格/全角空格），剩余部分按 区 / 栋(幢/座) / 单元 / 层(楼) / 号 切分，
  分别映射层级 1/2/3/4，`号` 段为房屋名称；缺失层级由 ensureChildNode 自动补齐，房屋挂最末级节点（无层级则直接挂小区）。
- 校验：编码/地址不能为空、地址前缀不符、同文件编码重复、库中编码已存在都会逐行报错；面积留空按 0。
- **两阶段导入**：先全量解析校验（含与库内编码比对），`Aborted=true` 时不写任何数据；全部通过后在**单个事务**里
  创建缺失层级 + 插入房屋，任一步失败整体回滚。返回体里的 `aborted/success/houses` 可用于判断是否落库。
- 导入逐行返回错误（最多 200 条），前端弹窗展示。

## 七、缓存、存储与任务

- Redis key 前缀可配置（默认 `web:`）；重要键：`auth:online`（在线集合）、`captcha:<id>`、`perm:user:<id>` 等。
- 存储：`pkg/storage` 支持 local 与 OSS（签名 URL、PresignPut、Exists），前端用 `StorageKeyManager` 管理本地缓存版本。
- 定时任务：`sys_job` + scheduler（`shell_enabled` 默认关闭，勿随意开启）。
- 开放接口：`/api/v1/open/**`，需配置 `integration.api_key`。

## 八、性能约定

- **禁止循环查库**：集合类场景（在线用户、菜单、房屋、住户）先收集 ID 去重，再 `WHERE id IN (...)` 批量查询，内存拼装。
  在线用户曾经因为「每个会话查一次用户表」让 `/dashboard/summary` 在 360 会话时退化到 17s，现为单次批查询（< 1s）。
- 列表默认分页（`PageQuery`，上限 200），大表查询必须命中 `community_id + deleted` 复合索引。
- 慢 SQL 阈值 `mysql.slow_threshold_ms`（默认 200ms），GORM 会打印慢查询。
- `e2e-api.mjs` 含性能回归断言：工作台统计必须在 2s 内返回。

## 九、前端约定

- 路由为 hash 模式（`/#/property/...`）；菜单与权限全部来自后端。
- 按钮权限：`v-auth="'property:structure:create'"`。
- 字典：`fetchGetDictData('space_node_type')`（登录即可读）。
- 当前小区：`usePropertyCommunity()`（`localStorage: property.currentCommunityId`），进入页面自动选择并跨页沿用；
  无小区时展示「暂无管理小区」提示。
- 接口统一封装在 `web/src/api/*.ts`，类型在 `web/src/types/api/*.d.ts`。
- **选房统一组件**：`web/src/views/property/components/house-cascader.vue`（基于 `GET /property/houses/cascader?communityId=&usageType=`
  返回的「层级 + 房屋叶子」级联树，value 形如 `n-<节点ID>` / `h-<房屋ID>`）；单位/车辆/住户/访客页面统一使用，
  传 `v-model` 即得到 houseId，保存时无需再传房号文字。
- **注意**：`request.post/put` 的 `params` 会被封装层自动转成 **JSON body**（`web/src/utils/http/index.ts`）；
  若后端按查询参数取值（如 `?communityId=`），请直接拼到 url 上，否则后端读到 0 会报"请选择小区"。
- 构建前需 `pnpm build`（`vue-tsc` 依赖构建生成的 auto-imports 类型，直接跑 `vue-tsc` 会全量报错）。

## 十一、常见坑

| 现象 | 原因与处理 |
| --- | --- |
| 迁移报 `Duplicate column name` | 见 4.2，删版本记录 + 重启（EnsureSchema 自愈） |
| 软删后新增同编码报唯一冲突 | 唯一索引需带 `deleted` |
| 更新影响 0 行但无报错 | DSN 缺 `clientFoundRows=true`（GORM 判定用 RowsAffected） |
| 前端 `vue-tsc` 大量报错 | 尚未 `pnpm build` 生成 `auto-imports.d.ts` |
| 菜单分组点开报路由嵌套错误 | 分组 path 必须是子页面 URL 前缀 |
| 登录后菜单缺失 | 角色未授权对应菜单；超管不受限 |
| 员工登录看不到数据 | 角色未绑定可管理小区、也没直接授权小区 |
